# 老師來講解：電腦怎麼「看懂」車牌？

嗨同學，今天我們來拆解 `YOLOv8_PP-ocr.py` 這支程式，看看電腦是怎麼從一張機車照片，變魔術般地印出「851-NSN」這種車牌號碼的。

你可以把整個流程想成「找東西」跟「認字」兩件事，缺一不可：

1. **先找出車牌在哪裡**（物件偵測，YOLOv8）
2. **再把車牌上的字唸出來**（文字辨識，PP-OCRv6）

我們就照著程式執行的順序，一步一步講。

---

## 第一步：讀圖片

```python
img = cv2.imread(args.image)
```

這就跟你打開一張照片一樣，程式把圖片讀進記憶體，變成一堆數字（每個像素的顏色值）。電腦眼中沒有「車牌」這個概念，它看到的只是一張由數字組成的表格，長得像這樣：

```
[[ [255,200,180], [254,199,179], ... ],
 [ [250,195,175], ...              ], ...]
```

後面所有的「辨識」，其實都是在對這堆數字做數學運算。

---

## 第二步：把照片「整理」成模型看得懂的樣子（letterbox）

AI 模型通常只吃固定尺寸的圖片，這支程式用的 YOLOv8 模型要求輸入是 **640×640** 的正方形。但我們的照片通常是長方形（手機拍的可能是 1920×1080），直接硬壓扁會讓車牌變形，偵測效果變差。

所以 `letterbox()` 這個函式做的事情，就像是：

> 把照片等比例縮小，塞進一個 640×640 的灰色畫布正中間，上下或左右留灰邊補滿。

```python
def letterbox(image, size):
  h, w = image.shape[:2]
  scale = min(size / h, size / w)      # 算出縮放比例，保持原始比例不變形
  ...
  canvas = np.full((size, size, 3), 114, dtype=np.uint8)  # 填滿灰色(114)的畫布
  canvas[pad_y:pad_y + new_h, pad_x:pad_x + new_w] = resized  # 貼到正中間
```

這就像是你要把一張 A4 的照片放進正方形相框，又不想裁切，只好等比例縮小、四周補上灰邊。

---

## 第三步：物件偵測——「車牌在哪裡？」(YOLOv8)

這是整個流程的靈魂第一步。YOLOv8 是一個已經被「教過」認識車牌長什麼樣子的 AI 模型（別人訓練好的，我們直接拿來用，省去自己蒐集資料訓練的功夫）。

```python
session = ort.InferenceSession(PLATE_MODEL_PATH, providers=["CPUExecutionProvider"])
...
output = session.run(None, {input_name: blob})[0]
```

你可以把這段想成：把剛剛整理好的 640×640 圖片「餵」給模型，模型會吐出一堆「候選框」，每個候選框長這樣：

```
[中心點x, 中心點y, 寬度, 高度, 這裡是車牌的信心值]
```

模型一次會吐出 **8400 個候選框**猜測，但大部分根本不是車牌（信心值很低）。所以程式做兩件事來篩選：

1. **信心值門檔（`CONF_THRESHOLD = 0.25`）**：信心值低於 0.25 的框直接丟掉，太沒把握不要。
2. **NMS 去重疊（`cv2.dnn.NMSBoxes`）**：模型常常對同一塊車牌畫出好幾個重疊的框，NMS（非極大值抑制）就是「同一個地方只留信心值最高的那一個框，其他重疊的都刪掉」。

最後把座標從「640×640 的畫布座標」換算回「原始照片座標」（因為我們縮放、補灰邊過，要還原回去才能在原圖上標出正確位置）。

> 小結：這一步做完，我們手上有了一個或多個「這裡很可能是車牌」的矩形框座標。

---

## 第四步：裁出車牌，準備送去認字

```python
x, y, w, h, confidence = max(detections, key=lambda d: d[4])
plate = img[y0:y1, x0:x1]
```

如果照片中偵測到多張車牌（例如拍到好幾台機車），程式很單純地**只挑信心值最高的那一個**來辨識，並用原圖座標把那一小塊車牌影像裁切出來，多留 4 個像素的邊（`pad = 4`），避免把車牌邊框切得太緊。

---

## 第五步：文字辨識——「車牌上寫的是什麼字？」(PP-OCRv6)

找到車牌只是第一關，接下來要讓電腦「讀出」上面的英文字母跟數字，這靠的是另一個模型：PP-OCRv6。

### 5-1 前處理：把車牌圖片變成模型要的格式

```python
new_w = min(max(int(np.ceil(OCR_HEIGHT * w / h)), 16), 1280)
resized = cv2.resize(image, (new_w, OCR_HEIGHT), interpolation=cv2.INTER_LINEAR)
blob = ((resized.astype(np.float32) / 255.0 - 0.5) / 0.5).transpose(2, 0, 1)[None]
```

這段在做：
- 把圖片縮到固定**高度 48 像素**（寬度等比例跟著變），因為 OCR 模型訓練時就是吃固定高度的圖。
- 把顏色數值從 0~255 壓縮到 -1~1 之間（這叫「正規化」），因為模型訓練時用的就是這個範圍，餵它一樣範圍的資料它才認得。

### 5-2 模型輸出：一長串的「猜測結果」

```python
probs = ocr_session.run(None, {ocr_input_name: blob})[0][0]
```

模型吐出來的東西，形狀是 `(T, 18385)`——你可以想成：模型把這張車牌圖片，從左到右切成 T 個很細的時間步（像掃描一樣一格一格掃過去），**每一格都去猜「這裡的字元是哪一個」**，而字典裡總共有 18385 種可能的字元（英文字母、數字、中文字、符號……）。

### 5-3 CTC 解碼：把「每一格的猜測」拼成一句話

這是整支程式最燒腦，但其實概念很簡單的一段：

```python
indices, scores = probs.argmax(axis=1), probs.max(axis=1)
text, confs, prev = [], [], 0
for idx, score in zip(indices, scores):
  if idx != 0 and idx != prev:
    text.append(ocr_chars[idx])
    confs.append(float(score))
  prev = idx
```

想像模型掃過車牌時，同一個字可能連續好幾格都猜中同一個字（因為那個字在圖片上佔了好幾個像素寬），所以輸出可能長這樣：

```
_ _ 8 8 8 _ 5 5 _ 1 1 1 _ N N _ S _ _ N N
```

（`_` 代表「這裡沒有字」，也就是程式裡的 CTC blank，索引是 0）

這段程式做的事情就是：
1. 跳過空白（`idx != 0`）
2. 跳過跟前一格重複的字（`idx != prev`），避免把 "888" 誤認成三個 8

處理完上面那串，就會拼出 `851N S N`→ 清理後變成 `851-NSN`。這招叫 **CTC 貪婪解碼**，是語音辨識、文字辨識領域常用的技巧，簡單又好用。

### 5-4 機車牌的特殊處理：為什麼要切三次？

```python
candidates = [("full", crop), ("top 20% trimmed", crop[int(ch * 0.2):]), ("top 35% trimmed", crop[int(ch * 0.35):])]
```

台灣機車牌是**接近正方形**的（不像汽車牌是長條形），上半部通常是國旗、年份這類跟車牌號碼無關的裝飾，下半部才是真正的號碼。如果把整塊車牌（含上半部）直接縮到高度 48，真正的文字會被壓得太小，容易認錯或漏字。

所以程式很聰明地**試三種裁法**：
- 完整的車牌
- 去掉上面 20%
- 去掉上面 35%

三種都送去辨識一次，**最後比賽看誰認出的字最多、信心值最高**，就用那個結果。這是一種很實用的「土法煉鋼」小技巧，用多次嘗試來補強模型本身的限制。

## 第六步：印出結果

```python
print(f"偵測到的車牌號碼：{text}（平均信心值 {avg_conf:.2f}）")
```

平均信心值，就是前面辨識出每個字元時，模型對自己猜測有多「有把握」的平均分數（0~1 之間，越接近 1 越可靠）。

如果你加上 `--debug` 參數，程式還會額外開 5 個視窗，把每一步「電腦看到的畫面」都畫出來給你看：原圖、模型輸入（補灰邊後）、偵測框、送進 OCR 的裁切圖、最終結果圖。這對學習跟除錯非常有幫助，建議第一次跑的時候一定要加這個參數，實際看一遍整個流程。


## 課後重點整理

| 步驟 | 用到的技術 | 白話解釋 |
|---|---|---|
| 整理圖片 | letterbox | 等比例縮小＋補灰邊，塞進模型要的正方形畫布 |
| 找車牌 | YOLOv8 物件偵測 | 模型吐出一堆候選框，用信心值跟 NMS 篩出最可能的車牌位置 |
| 裁切 | 陣列切片 | 只留信心值最高的那個框，把那塊影像裁下來 |
| 認字 | PP-OCRv6 + CTC 解碼 | 模型逐格猜字元機率，再用「去重複、去空白」的規則拼成完整車牌號碼 |
| 機車牌優化 | 三種裁法比較 | 因機車牌文字只佔下半部，多試幾種裁切角度取最佳結果 |

這支程式最厲害的地方，在於**全程只用 ONNX Runtime 做推論**，不需要安裝沉重的 `ultralytics` 或 `paddleocr` 套件，整體環境輕量很多，很適合拿來理解「物件偵測 + OCR」這個經典組合的基本原理。

下次看到停車場的車牌辨識系統，你就知道它背後大概也是這樣「先找框、再認字」兩階段在跑的！
